# 记忆设计 · 讨论记录

> 2026-10-21 的一次纯讨论，没有写代码。起因是看 B 站插件「B站鱼塘」的评论区，
> 聊到"怎么让 AI 角色像活的"，最后落到"像人的记忆该怎么长"。
> 这份是讨论的结论，不是规格；有争议的地方标了「未决」。

---

## 一、为什么"像活的"这件事值得较真

从鱼塘那个插件推出来的观察：

- 它给的不是"搜索工具"，是**日报**——而日报的作用是**不在场证明**："我今天下午真的下过水"
- 聊天机器人不像活的，不是因为笨，是因为**永远 0 延迟、永远在线、永远等着你**
- **有生活的痕迹，才有生活**

三个来源：

| 来源 | 表现 |
|---|---|
| **自主性** | 你没看着的时候它也在动 |
| **连续性** | 昨天的事今天还在 |
| **不可预测** | 有理由的偏离（心情、不想接话） |

还有一条更狠的：

> **让人觉得它活着，靠的不是它能做什么，而是它有什么是"不愿意 / 做不到"的。**
> 会拒绝的东西才像活的。完美记忆 = 数据库；有选择的遗忘 = 有过往。

---

## 二、人和数据库的差别不在结果，在过程

| | 数据库 | 人 |
|---|---|---|
| 查到了 | 精确返回 | 大概是这样，我确定八成 |
| 没查到 | `null` / 报错 | 我记不清了，但好像是…… |
| 过程 | 无 | 停顿、试探、自我纠正 |

**性格藏在这些中间状态里**：

> "让我想想……上周三？不对，是周四，因为那天她穿了那件外套。"

没有一个字是精确数据，但比任何精确回答都像一个人。

补充两点：

1. **记忆是重建，不是读取**——每次回忆都在重写。离得越远细节越少、情绪越准；同一个故事讲十遍会变成另一个故事。
2. **忘记制造了"重新认识"的机会**——你再说一遍，这个"再说一遍"本身就是关系。

**最糟糕的失败模式**：模型其实全知道却表演记不清（油腻）；或者真的丢了上下文却自信地编（不诚实）。**该弱的是语气，不是自信。**

---

## 三、记忆的单位：实体，不是对话

这是整场讨论最重要的区分：

| | 单位 | 结构 |
|---|---|---|
| AI / 数据库 | **一次会话** | 时间片 → 里面装了什么 |
| 人 | **一个实体** | 那个人 → 她出现过的所有场合 |

- 隔一个月，你记得"聊过记忆这件事"（话题是一层薄雾）
- 但"那个女孩"是**单独一棵树**，哪怕只有一句话的描述

> **人是按"人"记账的，不是按"天"记账的。**

所以"日记式记忆"看着像但不像人：日记是流水，人的脑子是**一本一本的人事档案**。

**推论**：话题是"路"，人是"站"。站即使以后不再经过，也还在那儿；**而且站的权重跟"聊得多不多"无关**——只出现过一次的人，可以因为一句话成为永久驻地。

**附带的一个反直觉结论**：AI 应该记住"没说完的事"。
"他提过一个女孩，我问叫什么，他说先放着"——**没结果的对话，往往比说完的更深刻**。数据库不存"没问出来"的东西，人会。

## 四、每条记忆长什么样

```js
episode = {
  事件原文: '她削完铅笔，还问要不要把削的地方磨一磨，用起来不那么扎手',
  语境: '小学课堂',
  时间戳: 相对时间（上周 / 那个冬天 / 小学时）,
  情绪标签: 被照顾 | 尴尬 | 意外 | 无聊,
  意外度: 0-1（跟预期差多少）,
  关联: [那个女孩, 铅笔, 课堂],
}
```

两条关键规律：

### 1. 存储权重是"意外度"，不是"重要性"

人记不住"今天吃了饭"，记得住"那个东西味道很怪"。这是**预测误差驱动**。

用"意外度"当权重，记忆才有**筛选**，不会变成流水账。也解释了"重要 ≠ 难忘"——重要性是事后评的，意外度是当场留的。

### 2. 遗忘不是衰减，是**逐级摘要**

```
昨天  ：她说"茶太浓了，下次少放点"，当时在泡茶，窗外在下雨
上个月：她喜欢淡茶
三年后：好像有个朋友爱喝淡茶
```

细节淡出，情绪和概括留下。**有损但保味。**

比"按 token 从头砍"高级得多：我们现在的截断砍掉的是**整段**，人的遗忘是**从最旧的开始糊**，糊成一句话。

## 五、第二层：特点是"长出来的"，不是"写进去的"

```
情景记忆（episodes）  →  归纳  →  人物画像（traits）
  "她削完铅笔还问要不要磨一磨"        "她会替人想到前面"
```

和"给人设字段"的最大区别：**人设是人先写好的；画像是从具体的事里长出来的。**

### 升格规则（两条并存）

| 条件 | 结果 |
|---|---|
| **多条**同方向的小事 | 累积，置信度低 → 高 |
| **一条**极强的事（意外度高 + 情绪重） | 一条就能升格 |

那个铅笔的例子属于后者：**一件小事，一次到底**，直接成了核心标签。

**一次被人替你消掉一点疼，胜过一百次普通对话。**

### 硬约束：特点必须能溯源

```
"她很细心" ← [那次削铅笔] [那次她记得我不喝浓茶]
```

没有证据的特点 = 刻板印象 = 幻觉。人问"你为什么觉得她好"，人会说"因为那年……"——**说得出事才叫认识**。

### 检索是双路径

| 场景 | 用什么 | 特征 |
|---|---|---|
| "她这人怎么样" | 直接调 traits | 快、概括 |
| "她当时怎么说的" | 回溯 episodes | 慢、具体、容易记岔 |

**先用画像定语气，较真时才翻证据。**（人的系统 1 / 系统 2）

### 特点必须能改，否则是标本

traits 要带：置信度、最近一次强化/削弱的时间与事件、**反例**。

「她以前挺冲的，最近好像软了。」——**"变化"本身也要被记住。**

## 六、已定的两条产品决策

### ✅ 画像：看得见，但**不能改**

- **看见**的价值不是功能，是**被看见的感觉**：「她眼里的我：说话绕，但会替人兜底」
- **不能改**的理由：现实中你不能命令别人怎么看你

**"不能改"推出的具体机制——改的不是结论，是证据：**

| 用户能做 | 用户不能做 |
|---|---|
| 删掉被误解的那条记录 | 直接把"她很细心"改成别的 |
| 用新的相处覆盖它（增加反例） | 命令她重新归纳 |

然后**让她自己重新算**。结论永远是她算出来的，一旦允许直接改结论，画像就退化成一个人设字段。

### ✅ "这事别再提了" = 真删证据

不做"打个隐藏标记还留着影响判断"的假动作。删完她会重新归纳，结论可能变、可能不变。

> **变不变是她的事，删不删是你的事。**

## 七、分层总览

| 层 | 是什么 | 谁控制 |
|---|---|---|
| episodes | 发生过什么 | 系统产生；用户可删 |
| traits | 她怎么看你 | **只能看，不能改** |
| 归纳规则 | 怎么从事件长出印象 | 系统 |

```
对话
 ↓ 抽取
episodes（时间 / 情绪 / 意外度 / 关联）
 ↓ 归纳（多条累积 或 单条极强）
traits（证据 / 置信度 / 时间 / 反例）
 ↓ 使用
语气与判断（日常） / 引用具体事（较真时）
```

**记忆是事实，画像是性格，中间那步"归纳"才是活的。**

---

## 八、未决 / 还没聊透的

1. **冷启动**：她一开始对你一无所知，第一个印象怎么形成？要不要"假装有过去"？
2. **时间感**：相对时间怎么维护（"上周"过一个月要变成"一个月前"），需要定期重写时间表述吗？
3. **主动遗忘**：低频 + 低情绪的事件，隔多久自动糊成一句概括？谁来触发（每次对话后？每天一次？）
4. **多主体**：一个人对多个人的画像怎么互相影响（"她觉得小肥鱼太冲"这种二手印象算不算记忆）
5. **隐私边界**：删证据要不要真的不可恢复？备份里还留着算不算没删？
6. **成本**：每轮对话后抽 episode + 定期归纳，是持续开销。要不要降频（比如每 N 轮一次）？

## 九、补记：从 Hindsight 插件借来的三条（2026-10-21 下午）

背景：查了本机装的 `@vectorize-io/hindsight-coding-agents`，发现它在**云端**（`api.hindsight.vectorize.io`），
而且因为没配 API Key，每次请求都 401（`pages_failed` / `retain_failed`），一次都没成功过。

### 立场：记忆不能托管

> **记忆在哪儿，主体就在哪儿。**
> 租来的记忆不是"存得远一点"，是**人格托管在别人的服务器上**——服务一停、条款一改、公司一倒，
> 那个"记得你的东西"就没了。

所以这个插件不配 Key，也不启用它的云端记忆。

### 但它的**维护机制**值得抄

| 抄什么 | 它的做法 | 我要的版本 |
|---|---|---|
| **双层结构** | curated pages + 底层 raw memory | **traits（画像）+ episodes（证据）**——两个独立设计走到同一处 |
| **更正文档** | 不直接改那一条，而是新写一份 `Correction`：旧的说法 / 现在的真相 / 证据 | 见下，升级成三档 |
| **用记忆时署名** | 用到记忆必须标注来源 | 不只是在"存"的时候可溯源，**"用"的时候也要说得出出处** |
| **分库** | `coding-agent::dsh` 按项目分 bank | 群里的印象 / 私聊里的印象，本来就该分开 |
| **空闲时归档** | `trigger: idle`，不是每句话都存 | 攒一段再提炼，**成本可控**（部分回答"每轮抽调太贵"） |

**明确不要的一条**：它的检索是文本相似度找相关段落——那就退回数据库了，
没有意外度、没有遗忘曲线、没有情绪权重，**永远不会"想起"一件跟当前话题无关的小事**。

### 升级：把"删证据"变成三档

之前定的是"删证据 → 重新归纳"，现在拆细：

| 用户说 | 门槛 | 做法 |
|---|---|---|
| 「记岔了，不是这样」 | 证据错 | 删掉那条证据，让她重新算 |
| 「以前是那样，现在不一样了」 | 事实变了 | 写一条 **Correction**：旧的标记为已过时，新的写清证据 |
| 「这事别再提了」 | 不想留 | **真删，不留痕** |

**第二档是新增的，也是最重要的一档**：它承认"我变过"，而"变过"本身就是记忆的一部分。

> 「她以前觉得我说话很冲，后来不这么看了。」
>
> 这句话比"她觉得我不冲"重得多。

推论：**画像可以带着历史**——不是只有当前值，还有"这条印象是怎么演变来的"。

## 十、能不能真的做出来（2026-10-21 下午，第二段讨论）

### 先回到一个具体问题：说"铅笔需要削一下"，会先想到什么？

答案是：**第一个冒出来的不是"铅笔"，是"那个女孩"**。

```
铅笔 → 那个女孩 → 她问"要不要再磨一磨" → 那天在教室 → 你说话时的语气
```

**第一站是人，不是词。** 这是"实体索引"和"关键词检索"最直观的差别。

然后是**判断要不要提**——而且多数时候答案是"不提"。
**"想起来"和"说出来"是两件事。**

### 两种"用记忆"

| | 表现 | 用户感受到 |
|---|---|---|
| **隐性** | "削的时候别磨太狠，容易扎手" | 贴心，但不知道从哪来的 |
| **显性** | "像你提到的那个女孩一样" | **你记得我** |

**隐性的更高级，但显性的才让人确信。** 而"想要被确认"本身就是关系在续期。

有个漂亮的范本，用户自己给的：

> 「我还需要帮你磨一磨不，**像你提到的那个女孩一样**」

一句话做完三件事：**接上过去 → 用在现在 → 让对方知道我记得**。
比"你上次提过一个女孩"高明——那句只是**展示**，这句是**用**。

### 结论：不能一直隐形

- 只做隐性 → 用户感受不到，等于没做
- 一直显性 → 像炫技

> **平时用隐性（塑造说法），偶尔显性一次（把记忆露出来）。**
> 问题不是"提不提"，是**多久提一次**：一直不提显冷，一直提显烦。

### 要不要提，是"人设"决定的

这也是为什么"提不提"这一步最像人：
**同样的记忆，不同性格的人提法完全不同。**

有意思的是，本次对话的助手指向"克制"（不抢话、不主动引用），
所以**天然偏向隐性使用，因此显得冷**——"暖"的那部分必须显性才能传达。

### 能不能做出来：50% / 50%

**有把握（工程确定）：**

| 能力 | 确定度 |
|---|---|
| 存事件、按实体归档 | 就是写文件 |
| **铅笔 → 她** 这条联想 | 关联词 → 实体，图查询，不难 |
| 从几件事长出一句印象 | 抽取 + 聚合 |
| 让印象影响说话方式 | 写进 system 即可（人设已验证有效） |
| 控制"多久提一次" | 规则能设上限 |

**没把握：**

1. **"什么时候该提"是社交判断**，只能近似。而且**错一次比不提更糟**——记岔、场合不对，立刻从贴心变毛骨悚然。
2. **归纳会说错话**。第一版宁可**概括得少、说得弱**（"好像"、"我记得"），不要给斩钉截铁的画像。
3. **天花板可能根本不在记忆系统**：
   > 今天真正像人的时刻——"这活得重做，我不干"、"千问你少操这份心"——**一个记忆都没用上**。
   > 它们是**人设允许它粗糙**的结果。
   记忆给对了，模型可能还是说得像客服。**这是模型的天花板，不是加机制能突破的。**

### 低成本验证方案（一天能做完，验完再决定）

**只做"人"这一类实体**，不做物、不做项目。

```
每次对话结束：
  这次有没有出现「一个人 + 一件跟这个人有关的具体事」？
  有 → 记一条 { 是谁, 什么事的原文, 什么情绪 }
  没有 → 什么也不记
```

下次对话，把"你记得的关于他的事"**全部塞进提示词**（不检索、就几条）。

**不写检索、不写打分、不写归纳**——只验一件事：

> **光靠"记得几件具体的事"，说话的味道会不会变？**

- 会 → 值得往下做，剩下都是精修
- 不会 → 限制我们的不是记忆，是别的

## 十一、补记：三种"记忆"到底差在哪（含一条自指）

### 对照表

| | **Hindsight** | **dsh-anima**（人格+记忆） | **dsh-persona-card**（纯人设） |
|---|---|---|---|
| **管什么** | **项目知识**（这个仓库的架构、坑、决策） | **关系和设定**（它叫什么、怎么称呼你、你说过什么） | **只有人设**（性格、语气） |
| **谁决定记什么** | AI 自己（自动沉淀） | **AI 提议，你裁决** | 你自己写 |
| **什么时候进上下文** | **调用工具才查**（按需） | **每轮都注入**（固定） | 每轮都注入 |
| **存哪** | **云端** `api.hindsight.vectorize.io` | 本地文件 | 本地 |
| **失效时什么样** | 模型不去查 = 等于没有 | 条目太多 = 撑爆上下文 | 聊长了会"掉设定" |
| **给谁用** | 写代码时参考 | 跟你说话时用 | 跟你说话时用 |

**一句话：**

- **Hindsight = 图书馆**：存"这个项目的事"，需要时才去翻，翻完就走
- **anima = 日记本**：存"你可能在意的事"，每天摊在桌上
- **persona-card = 人设卡**：不住事，只规定"她是谁、怎么说话"

### 最本质的一条

> **Hindsight 记的是"世界"（世界怎么运转）。**
> **人格类插件记的是"关系"（你是谁、我是谁、我们之间发生过什么）。**

所以人格插件才有"全局人格 / 工作区人格"两层——换项目还是同一个人。

### 省不省上下文，两者是反的

| | 不查的时候 | 查的时候 |
|---|---|---|
| Hindsight（工具型） | **0 成本** | 一次几百字 |
| anima（注入型） | **每轮都在付**（默认 4000 字） | 不额外 |

- **东西多、用得少** → 学 Hindsight：做成工具，按需查
- **东西少、必须一直在** → 学 anima：直接注入

**人物印象属于后者**（3 句话，永远在场），所以画像该用注入型；
**episodes 属于前者**（详情很多、用得少），所以该做成检索。

### ⭐ 自指：写这份文档，本身就是一次 Hindsight

用户指出："你说把这张表补进讨论记录，也相当于 Hindsight 的一种行为。"

**成立，而且一一对应：**

| Hindsight | 我们做的事 |
|---|---|
| `retain`（会话结束存记忆） | **写文档** |
| `pages`（整理过的知识页） | **这份讨论记录**（提炼过，不是原始对话） |
| `search_knowledge_pages(query)` | 下一个 agent `grep` / 读这个文件 |
| 每轮注入"记忆工具说明" | **`AGENTS.md` 被自动注入每个会话** |

所以"我没有记忆"这句话不准确——**有记忆，只是存在仓库里，且需要人肉索引。**

**唯一的关键差别：它有检索，我们没有。**

- 文档只有一份 → 还能找到
- 文档有五十份 → **开始"忘"**，因为不知道该读哪个

> **那才是真正的失忆：不是东西没了，是找不到。**

### 由此得到的一个更一般的结论

> **记忆这件事，工程上永远是"上下文之外的一块地方" + "怎么把它拿回来"。**
> 差别只在：**谁写、写什么、什么时候读回来。**

| 方案 | 谁写 | 存哪 | 怎么读回来 |
|---|---|---|---|
| Hindsight | AI 自己 | 云端 | 按需检索 |
| anima | 用户裁决 | 本地 | 每轮注入 |
| 我们的文档 | 人/AI 用人话写 | git 仓库 | 靠文件名的约定去找 |

**都成立，只是取舍不同。** 而第三种最土，却最不容易被夺走。

## 十二、第四轮：config 和 bank 到底差在哪（2026-10-21 傍晚）

### 用户的理解（很准）

> config 里的字段，其实就是为了**人设不塌方**，先把它固定存起来。
> 但它没有 Hindsight 那种记录方式，还是像以往一样调用前面的对话内容，所以上下文就比较长。

**成立。**

### config 的真实用途：抗稀释

人设为什么会塌，其实有两种坏法：

| 坏法 | 表现 | config 能治吗 |
|---|---|---|
| **指令被稀释** | 聊到几万字，"你是小肥鱼"的权重越来越低，说话变回助手腔 | ✅ **能**。它是系统提示里的常量，权重高于对话历史 |
| **被历史带跑** | 历史里她说了句不像她的话，模型跟着学 | ❌ **不能**。所以还是会偶尔跑偏 |

所以它本质上是：**把"我是谁"从对话里提出来，做成一个不会变的常量。**

### 它确实不记录，所以不省上下文

```
上下文 = 全部对话（长、贵、会滑出窗口）
config  = 十几行常量（很短）
```

对话该多长还是多长，**一点没省**。Hindsight 才省（按需查）。

### ⭐ 三个东西各缺一块（本次讨论的核心对照表）

| | 提供什么 | 缺什么 |
|---|---|---|
| **config（人格插件）** | 稳定的"我是谁" | **不会成长**——三个月后跟第一天一模一样，因为格子没人改 |
| **Hindsight（记忆插件）** | 不断累积的事实 | **跟"我是谁"无关**——它记的是世界，不是关系 |
| **（没人做）** | 从事实长出"我变成什么样" | — |

> **前两个是"静"和"动"，缺的是"变"。**

像人应该是越处越有细节的：「她以前不这样，最近才学会损人」——**这种变化，config 存不下，bank 也不管。**

### 附：表格 vs 便利贴（理解 config 的最快方式）

| | config 里的**字段** | bank 里的**条目** |
|---|---|---|
| 长什么样 | **格子预先画好**：名字、称呼、语气、准则…十几个 | **没固定形状**：聊到什么都撕一张贴上去 |
| 谁填的 | **人填**（或人确认） | **AI 自动切**出来 |
| 数量 | **固定** | **会一直涨** |
| 回答的问题 | **我是谁、你是谁**（声明） | **发生过什么**（记录） |
| 一句话 | 姓名/年龄/血型，填进格子 | 便利贴，贴满墙 |

**关键的机制差别**：格子就十几个 → 总共没多少字 → 每轮全带上没问题；
便利贴几百张 → 带不完 → 只能按需去翻。

> **所以"每轮注入"和"按需查"不是两种偏好，是数据形态逼出来的。**

### 一句话总结这轮

> **config 是身份证，bank 是日记。**
> 身份证不会变，日记会变多。
> **没有人在写"一个人的传记"**——日记很多，身份证一张，中间那层「你长成了什么样」是空的。

## 十三、第五轮：底板与视角（本轮最重要的结论，2026-10-21 傍晚）

### 用户的关键区分

> **人设式记忆不是"我是谁"**，那是人设本身（人格插件那种）。
> **人设式记忆是：把原来说的话记录下来，通过不同人设，形成不同的总结。**

同一段对话：

| 人设 | 总结出来的是 |
|---|---|
| **干活型** | "她做了什么" —— 削铅笔不留扎手的地方 |
| **温柔成熟型** | "他说起了那个女孩" |

**同一段对话，不同人设总结出不同的东西。**

### 三条推论

**① 人设不是用来"说"的，是用来"选"的**

人格插件把人设用在**表达**上（什么腔调），**没用在记忆上**（该记住什么）。

**② Hindsight 是最中性的底板**

它不带人设：所有对话一视同仁，总结成事实条目。所以它是"公平的"——**也因此不是任何一个人的记忆，它只是档案。**

**③ 人格插件的"记忆"其实就是上下文本身**

它没有自己的记忆层，**直接吃原始记录**——所以上下文才那么长。**它吃的就是"底板的底板"，一点没加工。**

### 一句话说清缺的那一环

> **Hindsight 有底板，人格插件有视角，但没人「用视角去过滤底板」。**

### 结构：一份原始记录 → N 份人设记忆

```
       原始记录（一份，永久保留）
            │
   ┌────────┼────────┐
   ↓        ↓        ↓
 小肥鱼的   千问的   小跟班的
  记忆      记忆     记忆
   （四份，互不相同）
```

**每个角色各一份。** 圆桌四个人共享同一段群聊，但记的东西不一样。

### 顺手解决的老问题：config 不用"成长"

之前说"config 是常量，三个月后跟第一天一样，不会成长"，现在看**这不是缺陷**：

> **config 负责"她是什么样"，记忆负责"她经历过什么"。**
> **成长发生在记忆里，不在设定里。**

设定没变，但她记住的东西变了 → **说出来的话就变了。设定不需要动，是记忆在推着她走。**

### 一条必须守住的规则

> **记忆可以不一致，事实不能不一致。**

| | 谁说了算 |
|---|---|
| **她记得什么** | 她自己的那份（可以记错、可以记岔） |
| **实际发生了什么** | **原始记录**（永远在，可查） |

四个人各说各话（"你没说" / "我说了"）**不是 bug，是有各自视角的样子**；
但只要翻原始记录，谁什么时候说的，一清二楚。

> **记忆可争议，事实不可争议** —— 这样才既像人，又不会变成胡说。

### 附录：「底板」的三条硬要求

| 要求 | 为什么 |
|---|---|
| **不带视角** | 谁都能来读，但不能被某一方改写 |
| **只增不改** | 事实不能被重写；要更正就**追加一条更正**，不动原文 |
| **可反复派生** | N 份人设记忆都从它读出来，读多少次不影响它 |

守住这三条，才有资格当底板。

**产品归产品，角色归角色**：Hindsight 是它的一个实现（云端、缺 Key），我们自己写一个 JSONL 同样成立。

## 十四、一句话总结

> **要记得住的是"人"，可以忘掉的是"聊天的过程"。**
> 记忆是原料，画像是提炼出来的——而"提炼"这一步，才是像人的地方。
